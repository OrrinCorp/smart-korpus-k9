# Розумний корпус · К9 ЧНУ (ННІФТКН)

Прототип системи «Розумний корпус» для навчального корпусу № 9 Чернівецького національного університету.
Команда «Ша-Пі-То»: Вакарюк Іван (дизайн і 3D), Шестобуз Олег (програмна частина), Реус Ірина (маскот «Шахеда»).

> Усі показники датчиків, енергоспоживання, події та розклад у прототипі **демонстраційні** (ТЗ п. 2, 4).
> Групи, викладачі й користувачі доступу вигадані або знеособлені.

## Два застосунки

| Файл | Для кого | Що є |
|---|---|---|
| `index.html` | **Адміністрування**: адміністратор, відповідальна особа, гість-глядач | 3D-карта з датчиками, сценарії, доступ, живлення, комутація, енергія, безпека, розклад, події |
| `student.html` | **Студенти** (на телефоні) | Лише онлайн-розклад, «зараз / далі», розклад подій, пошук аудиторії, вільні аудиторії, оголошення. **Без карти, датчиків і керування** |
| `tests/selftest.html` | Команда | Автоматична самоперевірка (35 тестів) |

Збирач і сервер не потрібні: відкрийте файл у Chrome, Edge або Firefox. Відкриті в одному браузері, обидва
застосунки синхронізуються через `localStorage`: подія чи оголошення з панелі одразу з'являються у студентів.
Пряме посилання на вкладку: `index.html#scenarios`, `#access`, `#power`, `#wiring`, `#devices`, `#tour`.

## Корпус

Блоки **А** і **Б** мають по **5 поверхів**:
- **поверх 0** — хол і вестибюль, пост охорони, гардероб, буфет, службові приміщення;
- **на кожному поверсі** обох блоків — санвузли жіночий і чоловічий та кімната для куріння;
- **адміністративне приміщення А-001** (диспетчерська) разом із **серверною А-002** і **електрощитовою А-003** (АВР, ГРЩ);
- **поверхи 1–4** — аудиторії, комп'ютерні класи, лабораторії, кафедри.

Перемичка між блоками — на рівні 1-го поверху. Поділ на приміщення демонстраційний (`js/data/building.js`).

## Інтерактивна карта

- **Ліва панель «ліфт»**: поверхи 4…0 і «Усі»; під ними режими **▦ План** (вигляд згори на поверх, перетягування — зсув, великі підписи), **☰ Поверхи** (розведені по висоті), **Aa** (підписи), **⌂ Огляд**.
- При виборі поверху нижчі поверхи лишаються ледь помітними для орієнтації; компас «Пн» показує північ; підписи ховаються, коли камера далеко.
- **Підписи на всіх приміщеннях** (аудиторії, санвузли, сходи, службові): видно при виборі поверху або кнопкою «Aa» для всіх поверхів.
- **Пошук** приміщення в рядку «Пошук: А-305» (Enter); підсвітка приміщення під курсором.
- **«☰ Поверхи окремо»**: поверхи розводяться по висоті, щоб було видно всі одночасно.
- **«◎ Виділити»** (у картці приміщення): решта корпусу стає прозорою, лишається одна кімната.
- **Модель кімнати**: подвійний клік або кнопка «🔍 Модель кімнати». Відкривається окрема 3D-модель приміщення: стіни з дверима й вікнами
  (стіни біля камери «зрізаються»), меблі за типом, люди за PIR, жалюзі й світло за сценарієм, пристрої на місцях, кабелі до розподільчої
  коробки і далі до шафи. Перемикачі шарів, ◀ ▶ — сусідні приміщення. Адміністратор може завантажити **власну .glb-модель кімнати**
  (вписується в габарити, зберігається в браузері; або файл `assets/models/rooms/<номер>.glb` при роботі через http).
  Пряме посилання: `index.html#room=А-305`.

## Журнал подій

Журнал за замовчуванням показує **усі** події. Коли несправність усунуто, пов'язані події не зникають: вони закриваються автоматично з позначкою «✓ усунуто о ГГ:ХХ» і лишаються в історії.

## Ролі

| Роль | Що бачить |
|---|---|
| Гість / глядач | Огляд (без енергії), Аудиторії (статуси), Події, Комфорт, Територія. Без енергії, моделі кімнати, пристроїв, журналів, комутації, керування, тривог і несправностей, службових сповіщень |
| Відповідальна особа | + Енергія, модель кімнати, Сценарії (ручне керування), Безпека (підтвердження подій), Доступ (двері й журнал, без користувачів), Живлення (перегляд); пристрої без мережі й живлення, без портів і топіків |
| Адміністратор | Усе: комутація, обладнання, налаштування, редагування правил, користувачі доступу, тести |

## Модулі панелі адміністрування

| Вкладка | Що робить |
|---|---|
| Огляд | Зведення: статуси аудиторій, люди, клімат, потужність, сповіщення, пристрої, парковка |
| **Керування → Диспетчерська А-001** | Робоче місце оператора: стан корпусу, **ручне керування** приміщенням (кнопка ⏻ на кожному пристрої, «вимкнути все»), двері (відчинити на 5 с, тримати, заблокувати, за відбитком; закриті зони — лише адміністратор і з причиною), світло поверху, список ручних вимкнень, **журнал команд**. Кожна команда йде шляхом А-001 → сервер → MQTT …/set → шафа → контролер → пристрій; якщо шафа чи контролер недоступні — «не доставлено» з причиною |
| Аудиторії | Статуси, конфлікти розкладу, зміни розкладу, бронювання (адміністратор / відповідальна особа) |
| **Події** | Розклад подій інституту: створення й редагування, аудиторія, кому адресовано; оголошення для студентів |
| **Сценарії** | Редактор сценаріїв (світло, жалюзі, проєктор, онлайн-дошка, уставка, вентиляція, ПК, двері) і правил з пріоритетами: відключення живлення → ручний режим → за часом → за розкладом → присутність → нічний режим → автовимкнення. Масове застосування за блоком / поверхом / типом, ручний режим із терміном дії, журнал змін |
| Комфорт | Моніторинг CO₂, температури, світла; кімнати для куріння (люди, PM2.5, витяжка, двері); порівняння «з автоматикою / без» |
| Безпека | Стан систем, тестові події, журнал з підтвердженням і CSV |
| **Доступ** | Безключовий доступ **за відбитками пальців**: двері й режими, групи доступу (зони + час), знеособлені користувачі, реєстрація й видалення шаблонів, симуляція проходу, журнал проходів |
| Енергія | Графіки за добу й тиждень, заощадження, поріг |
| **Живлення** | Три рівні резерву: ДГУ через АВР → центральний онлайн-ДБЖ N+1 (сервер, мережа, диспетчерська) → власний ДБЖ у кожній шафі (контролери, датчики, зчитувачі, замки, ~6 год). Однолінійна схема, стан усіх шаф, імітація відключення мережі, несправностей ДГУ, АВР, АКБ і палива, тестовий пуск ДГУ |
| **Комутація** | **Несправності видно прямо в портах контролерів** (червоний порт із хрестиком — несправний пристрій, блимає — тривога, сірий — немає живлення чи контролер offline, блідий — обрив зв’язку шафи). **Імітації керуються зі схеми**: обрив вводу шафи, несправність АКБ, обрив зв’язку, відмова контролера, несправність пристрою, тривога від датчика; демо — `index.html#wiring&admin&simdemo`. **Клік по порту, рядку чи маркеру** — на плані лишаються тільки цей пристрій, його приміщення й траса кабелю (пристрій → РК → лоток коридору → шафа), решта індикаторів ховається; клік по модулю — усі лінії контролера; посилання `index.html#wiring&admin&dev=<ID>` (пристрій) або `#wiring&admin&inst=ЩА-А2/KR1` (контролер). Пристрій → розподільча коробка приміщення → шафа ЩА → контролер → порт → кабель; компонування шафи (клік по порту — пристрій на карті); живлення шаф від ГРЩ через ДБЖ; топологія мережі; кабельний журнал |
| Територія | Парковка P1/P2, зона відпочинку, майданчик ДГУ |
| Обладнання i3 | Контролери Atom (кількість — з фактичного розподілу портів), реєстр ~1000 пристроїв, пошук |
| Налаштування | Імпорт .glb-моделі, скидання демо-даних |

## Тема оформлення

Кнопка ☾ / ☀ у шапці (панель і студентський застосунок) перемикає світлу й **чорну** тему. За замовчуванням — як у системі;
вибір запам'ятовується на пристрої. У чорній темі перемальовуються й 3D-карта (земля, сітка, підписи, приглушені кольори),
і модель кімнати.

## Як вставити готову 3D-модель

Роль «Адміністратор» → «⬆ 3D-модель» → файл `.glb` (1 одиниця = 1 м). Якщо меші названі номерами аудиторій
(`А-301`, `A_301`, `room_B-105`), вони стануть клікабельними. Докладніше — [assets/models/README.md](assets/models/README.md).

## Важливі обмеження

- **Біометрія.** Відбиток пальця — чутливі персональні дані. Шаблони мають зберігатися лише в зашифрованому вигляді
  на сервері або контролері доступу, потрібна письмова згода, а для тих, хто не погоджується, — альтернатива (картка або PIN).
- **Евакуація.** Двері на шляхах евакуації розблоковує сертифікована система пожежної сигналізації, а не прототип.
- **Живлення.** Потужності ДГУ й ДБЖ орієнтовні; проєкт робить проєктувальник електропостачання.
- **Комутація.** Кількість портів контролерів умовна; її треба звірити з документацією i3 Engineering.
- **Кімнати для куріння.** Є на кожному поверсі обох блоків (А-x19 біля сходів 2, Б-x13 у північній частині) з окремою витяжкою,
  датчиком PM2.5, PIR і дверима з доводчиком. **Увага:** ст. 13 Закону № 2899-IV забороняє куріння в приміщеннях закладів освіти —
  облаштування таких кімнат треба погодити з адміністрацією ЧНУ та юристом. Тип приміщення `smoking` у `js/data/building.js`.

Офіційні плани поверхів, офіційний розклад, моделі контролерів і формат MQTT-топіків (з i3 Engineering),
постачальник біометричного доступу, проєкт електропостачання.
